# Visual reading companion — next feature plan

Requested 19 October 2026. Planning only; not part of test build27 and no subscription activation.

## Reading flow

Open the companion beside the current book and passage. Suggested actions: “Who is this?”, “Show relationships”, “Where are we?” and “Build a timeline”. Readers can also ask in ordinary language. Keep the book title and current chapter visible, remember conversation per book, and return to the same reading position. Default to evidence up to the current chapter; offer an explicit full-book/spoiler setting.

## Three views

- **People:** clean cards with names, aliases and roles; a focused relationship diagram with labelled connections. Start with the selected character and a few direct links, expand on demand. Provide a searchable text list and tap-through passage citations.
- **Places:** a compact place list and route view. Use geographic coordinates only when supported; fictional or uncertain geography uses a clearly labelled schematic. Never invent precise locations. Each place/route links to its source passages.
- **Timeline:** an ordered vertical chronology with event title, date when stated, chapter and evidence. Distinguish exact dates, approximate dates and narrative sequence. Parallel strands are optional; mobile starts with one readable column.

## Visual and interaction rules

Use the book's warm reading palette, restrained accent colours, readable labels and generous touch targets. Keep dense graphs out of the initial mobile view. Tap expands a card; focus/zoom is explicit, with reset and an accessible list alternative. Support dark mode, large text, arbitrary book languages and ruby where available. Do not force horizontal scrolling in the reader. Save useful views with the book for offline reopening.

## Correctness, privacy and cost

Every factual node/edge/event has stable book-edition/chapter/passage references. Label textual facts separately from interpretation and unknowns; ambiguity offers candidate names rather than invented certainty. Validate generated structured data before rendering. Key reusable public-book packs by edition/content revision, language and spoiler scope; deduplicate concurrent requests. Personal questions, drafts and private uploads remain private. A changed edition invalidates only affected cached views.

## Possible Reading plan scope

Ordinary books, dictionaries, offline reading and available cached companion packs remain included. Optional paid usage can cover new AI-generated visual guides and conversational follow-ups, with clear estimated usage and existing account-bound quota checks. Reader/Creator/Entrepreneur names stay consistent. Exact allowances and any public-plan activation need their own qualification; this plan does not change products, prices or purchased rights.

## Delivery sequence and acceptance

1. Current-book contextual questions, cited character cards and accessible relationship view.
2. Cited chronology and place list/schematic, then verified geographic routes where useful.
3. Edition-aware shared pack reuse and optional metered generation.

Qualify representative Chinese/Japanese/English books with ambiguous names, changing relationships, undated events, fictional places and renamed editions. Check chapter-only spoiler boundaries, incorrect/unsupported model output, offline cache, duplicate jobs, account switching, phone keyboard/large text and Mac resize. A missing source must remain visible as uncertainty. Preview real book-derived examples before any subscription launch.
